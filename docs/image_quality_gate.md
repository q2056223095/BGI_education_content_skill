# 图片自动质检与失败重做｜V1.1（硬门槛）

## 为什么要改
上一批出现“有画面但没文字”“标题/要点不完整”“双联拼版被当作一张”等问题。这不是美术问题，而是错误地把背景图、文字稿和最终发布图混为一体。**生成一张好看的背景，不等于生成一张可发布的小红书成品。**

## 强制改成四段式流程
1. **事实锁定**：先有核实后的正文、P1和P2标题、P2的2–3个解释要点、两页来源身份角标，保存为两份 JSON spec。未核实的数字、课程/合作、政策解读一律不进spec。
2. **只生成背景（禁止让生图模型绘制任何文字）**：生成两张不同构图、独立3:4的纯场景画面，提示词须含“no text, no letters, no logos, no symbols resembling text, leave title safe area”。先视觉检查背景确实无乱码、文字、假学校标志、拼图、无版权肖像；检查通过后设置 spec.background_verified_text_free=true，未通过先重做背景。
3. **中文文字后期叠加**：使用 Pillow 的 \`scripts/render_and_validate.py\` 将**精准的中文**、标签/免责声明程序化写到背景上。文字不交给图像生成模型“猜”，不允许只有景没有字。脚本强制字体、数量、行数、边界、大小、来源身份；输出 P1.png/P2.png + P1.qa.json/P2.qa.json。
4. **双重验收后才计入完整**：
   - 机器门槛：render_and_validate.verify + verify_batch.py，验证2张各1080×1440 PNG、文字合成元数据、图文 spec 哈希、像素绘制、无缺页/重复、文案存在；
   - **视觉/语义门槛**：实际查看P1/P2（包括手机缩略图）确认中文可读且无错字、文字与背景未互相遮挡、文字事实一致、科学边界正确、无误导真实校园/学员场景；程序化校验并不理解图片中的事实和真假，所以视觉检查不能被机器哈希替代。

## P1最低门槛
- 必须有清晰中文主标题（建议8–22字、1–3行），准确具体，手机端能识别。
- 必须有说明文字/副标题（说明对象或事实边界）。
- 必须有来源身份角标；AI概念图标“AI教育概念示意图｜非真实现场”；科研机制图标“AI科学示意图｜非原始数据图”。
- 无拼版、无裸背景、无假Logo或伪实拍机构现场。

## P2最低门槛
- 必须有中文解释标题 + 2至3条实质要点（每条简短标题与解释句）。
- 每条解释对应正文及来源，不用空卡片、icon或空白条占位。
- 必须有来源身份角标及必要限制，不能把编辑总结写成官方课程大纲。
- 如果P2只有照片而没有标题/解释，**直接FAIL**；只给文字而无主题画面也要退回改图。

## 自动失败重做（每张最多再试2次）
场景失败（有伪文字/拼版/不合事实/可读区不够） → **重做背景**；
文字超界、字体缺失、内容项为空 → **先修标题或要点 spec 再重新叠加**；
视觉检查失败（文字压主视觉/字号太小/遗漏政策边界/误导） → 调整版式、背景或文字 → **重新叠加**；
出现乱码/错字 → 校对spec → 重新叠加；不要再让生图模型随机生成汉字。
最多2次重试后，保留合格文件，记录失败次数、错误和缺件，成品状态只能标“部分完成”，不得把不合格图计入PNG合格数，也不得在批次报告标“全部完成”。

## 推荐的文件结构
01_选题/
  小红书文案.txt
  来源与合规.md
  P1.background.png   # 内部素材，不应作为成品发布
  P1.spec.json         # 最终版中文文本及视觉身份，已核验
  P1.png               # 最终成片
  P1.qa.json           # 机器自检记录
  P2.background.png
  P2.spec.json
  P2.png
  P2.qa.json

可把原始背景单独存于内部素材目录，防止误选图片发布。最少必须保留P1/P2的spec、QA JSON、成片PNG供批次验收使用。

## 命令示例
需安装 Pillow>=10 和支持中文的字体（例如 Noto Sans CJK，必须是系统已有或经合法途径安装；仓库不要提交/分发字库）。

\`\`\`bash
python scripts/render_and_validate.py render --background 01_选题/P1.background.png --spec 01_选题/P1.spec.json --out 01_选题/P1.png
python scripts/render_and_validate.py verify --image 01_选题/P1.png --spec 01_选题/P1.spec.json
python scripts/render_and_validate.py render --background 01_选题/P2.background.png --spec 01_选题/P2.spec.json --out 01_选题/P2.png
python scripts/render_and_validate.py verify --image 01_选题/P2.png --spec 01_选题/P2.spec.json
python scripts/verify_batch.py --batch 2026-11-09
\`\`\`

## 证据和边界
- 机器QA记录的是“脚本已按spec绘制准确文字并且文件未被改动”，**不等于OCR/语义识别**，不能据此自动确认事实正确或无视觉遮挡。
- 背景的无字状态需视觉确认；切勿在一个有生图乱码的底图上再加文字。
- 不能以修改spec让错误标题“通过QA”来掩饰事实问题；spec必须事先与来源、正文、图文事实对齐。
- 若运行环境没有Pillow/中文字体/可用文件系统，明确标为阻塞并保留已完成文案；不能退回“生成一张没有字的漂亮画面”。
